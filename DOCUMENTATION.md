# BlumScript — полная документация

**Версия:** 0.2.0
**Компилятор:** `blumsc` (Rust)
**Бэкенд:** генерация C99 → нативная компиляция (MSVC / GCC / Clang)

---

## 1. Что такое BlumScript

BlumScript — универсальный компилируемый язык, спроектированный с двумя целями одновременно:

1. **Низкий порог входа.** Все ключевые слова — обычные английские слова (`let`, `var`, `func`, `if`, `else`, `while`, `for`, `return`, `struct`, `import`, `and`, `or`, `not`, `sizeof`, `cast`). Синтаксис читается как псевдокод.
2. **Максимальные возможности.** Язык даёт прямой доступ к памяти: указатели, `malloc`/`free`, арифметика указателей, `&`/`*`, `->`, `sizeof`, приведение типов `cast<T>(...)`, сырые вставки C через `asm { ... }`.

Один и тот же язык позволяет писать:
- высокоуровневые приложения (функции, структуры, циклы, строки);
- низкоуровневый код (ручное управление памятью, указательная арифметика, работа с сырой памятью).

**Модель исполнения.** BlumScript компилируется в C, а C — в нативный исполняемый файл (`PE/COFF` на Windows). Никакой VM, никакой интерпретации в рантайме. Скорость и ABI — как у C.

## 2. Архитектура компилятора

```
исходник .blm
   │
   ├─ driver::expand_imports   — рекурсивное раскрытие import "..."
   ├─ lexer::lex               — токенизация
   ├─ parser::parse_program    — рекурсивный спуск → AST
   ├─ codegen::generate        — семантическая проверка + генерация C
   ├─ запись .c файла
   └─ driver::compile_c        — вызов cl.exe / gcc / clang → .exe
```

Модули (`src/`):

| Файл | Назначение |
|------|------------|
| `lexer.rs`  | Токены, литералы, комментарии, `asm { … }` как сырой блок |
| `ast.rs`    | Определения AST (выражения, операторы, объявления) |
| `parser.rs` | Рекурсивный спуск, приоритеты операторов, разбор типов |
| `types.rs`  | Система типов, отображение в C-типы |
| `codegen.rs`| Проверка типов, вывод типов, генерация C-кода |
| `driver.rs` | Импорты, поиск компилятора C, сборка, запуск |
| `main.rs`   | CLI `blumsc` |

Семантический анализ выполняется в `codegen` (вывод типов, проверка областей видимости, полей структур, сигнатур функций, типов операндов). При ошибке компиляция останавливается до записи `.c`.

## 4. Быстрый старт

Создайте `hello.blm`:

```blumscript
func main() -> int {
    print("Hello, BlumScript!");
    return 0;
}
```

Сборка и запуск:

```powershell
blumsc run hello.blm
```

Вывод:

```
built: hello.exe
Hello, BlumScript!
```

Или отдельно:

```powershell
blumsc build hello.blm -o hello.exe
.\hello.exe
```

## 5. CLI

```
blumsc build <file.blm> [-o output.exe] [--emit-c]
blumsc run   <file.blm> [--emit-c]
blumsc check <file.blm>
blumsc tokens <file.blm>
blumsc ast    <file.blm>
```

| Команда | Действие |
|---------|----------|
| `build` | Скомпилировать в `.exe`. `-o` задаёт имя. Рядом создаётся `.c` файл. `--emit-c` печатает сгенерированный C в stdout. |
| `run`   | Собрать и сразу запустить. Код возврата программы пробрасывается. |
| `check` | Только лексика + парсинг + семантика/кодогенерация. Ничего не собирает. |
| `tokens`| Дамп токенов. |
| `ast`   | Дамп AST в отладочном виде. |
| `-h`, `--help` | Справка. |
| `-V`, `--version` | Версия. |

## 6. Лексика

### Комментарии
```blumscript
// однострочный
/* многострочный
   комментарий */
```

### Литералы

| Вид | Пример |
|-----|--------|
| Целое | `42`, `0`, `1000000`, `0xFF`, `0x1F` |
| Дробное | `3.14`, `0.5`, `2.0` |
| Строка | `"hello"`, `"line\nbreak"`, `"\t"`, `"\"quoted\""` |
| Символ | `'a'`, `'\n'`, `'\\'` |
| Логические | `true`, `false` |
| Нулевой указатель | `null` |

Экранирование строк: `\n`, `\t`, `\r`, `\0`, `\\`, `\"`.

### Идентификаторы
Начинаются с латинской буквы или `_`, далее буквы, цифры, `_`. Регистрозависимы.

### Ключевые слова
`let`, `var`, `func`, `if`, `else`, `while`, `for`, `return`, `break`, `continue`, `true`, `false`, `null`, `struct`, `import`, `asm`, `sizeof`, `cast`, `and`, `or`, `not`.

### Операторы
`+  -  *  /  %` — арифметика
`<  >  <=  >=  ==  !=` — сравнения/равенство
`and  or  not`, `&&  ||  !` — логика
`&  |  ^  ~  <<  >>` — битовые
`=` — присваивание
`&` — адрес, `*` — разыменование (унарные)
`.` и `->` — доступ к полю структуры
`[]` — индексация
`()` — вызов/группировка

## 7. Типы

### Примитивы

| BlumScript | C-тип | Описание |
|------------|-------|----------|
| `bool`   | `bool`    | логический |
| `char`   | `char`    | символ, 1 байт |
| `byte`   | `uint8_t` | беззнаковый байт |
| `int`    | `int64_t` | знаковое 64-бит |
| `uint`   | `uint64_t`| беззнаковое 64-бит |
| `float`  | `double`  | число с плавающей точкой (двойная точность) |
| `double` | `double`  | синоним `float` |
| `string` | `char*`   | строка C (NUL-terminated) |
| `void`   | `void`    | отсутствие значения |

### Производные типы

```blumscript
*int          // указатель на int
**int         // указатель на указатель
*Point        // указатель на структуру Point
int[16]       // массив из 16 int (в типах)
```

### Приведение типов

```blumscript
cast<*int>(malloc(sizeof(int)))   // void* → *int
cast<int>(3.9)                    // double → int (усечение)
cast<string>(ptr)                 // любой указатель → string
```

### Размер типа

```blumscript
sizeof(int)     // 8
sizeof(Point)   // размер структуры
```

## 8. Переменные и области видимости

```blumscript
let x: int = 10;       // let — «неизменяемая» по замыслу (в C статически не проверяется на переприсваивание)
var y: int = 20;       // var — изменяемая
let z = 5;             // тип выводится из инициализатора
```

- `let` и `var` обязаны иметь инициализатор.
- Явная аннотация типа пишется через `:`.
- Если тип указан явно и отличается от типа выражения, генерируется приведение.
- Область видимости — блок `{ }`. Вложенные блоки могут перекрывать имена.
- **Глобальные переменные:** объявления `let`/`var` верхнего уровня транслируются в файловые `static`-переменные и инициализируются в начале `main`. Они видны из всех функций.
- Присваивание возможно как простой переменной, так и lvalue: полю структуры (`p.x = …`, `p->x = …`), элементу массива (`a[i] = …`), разыменованному указателю (`*p = …`).

## 9. Выражения

### Арифметика и сравнения
```blumscript
let a: int = 10 + 3 * 2;      // 16
let b: float = 3.5 / 2.0;
let c: bool = a >= 15 and a != 7;
let d: int = a % 5;
```

### Логика
`and` / `&&`, `or` / `||`, `not` / `!` — с коротким замыканием (C-семантика).

### Битовые операции
```blumscript
let mask: int = 1 << 4;       // 16
let inv: int = ~mask;
let x: int = 0xF0 | 0x0F;
```

### Приоритет операторов (от низкого к высокому)

1. `=` (присваивание, правоассоциативное)
2. `or`, `||`
3. `and`, `&&`
4. `|`
5. `^`
6. `&`
7. `==`, `!=`
8. `<`, `>`, `<=`, `>=`
9. `<<`, `>>`
10. `+`, `-`
11. `*`, `/`, `%`
12. унарные `-`, `not`, `~`, `*`, `&`
13. постфиксные: вызов, `[]`, `.`, `->`

### Указательная арифметика
```blumscript
var arr: *int = cast<*int>(malloc(sizeof(int) * 10));
arr[0] = 1;          // индекс
*(arr + 1) = 2;      // арифметика указателей + разыменование
```

### Доступ к полям
```blumscript
p.x        // структура по значению
p->x       // структура через указатель
```
Компилятор сам выбирает `.` или `->` в зависимости от типа базы, но синтаксис тоже учитывается.

## 10. Управляющие конструкции

### if / else
```blumscript
if (x > 0) {
    print("positive");
} else if (x < 0) {
    print("negative");
} else {
    print("zero");
}
```
`else if` поддерживается напрямую (как цепочка условий).

### while
```blumscript
var i: int = 0;
while (i < 10) {
    i = i + 1;
}
```

### for
Трёхчастный, как в C:
```blumscript
for (var i: int = 0; i < 10; i = i + 1) {
    print(i);
}
```
Допустимы `let`/`var` в инициализации, присваивание или выражение — в обновлении.

### break / continue
```blumscript
for (var i: int = 0; i < 100; i = i + 1) {
    if (i == 5) { break; }
    if (i % 2 == 0) { continue; }
    print(i);
}
```

### return
```blumscript
return 0;
return x + 1;
```

### Блок
```blumscript
{
    let tmp: int = 42;
}
```

## 11. Функции

```blumscript
func add(a: int, b: int) -> int {
    return a + b;
}

func greet(name: string) {
    print("Hello, ", name);
}
```

Правила:
- Параметры типизированы: `имя: тип`.
- Возвращаемый тип указывается через `-> тип`. Если отсутствует — `void`.
- Вызов: `add(3, 4)`, `greet("world")`.
- Аргументы приводятся к типам параметров автоматически (числовые/указательные приведения).
- Поддерживается рекурсия.
- Точка входа: `func main() -> int`. Компилятор переименовывает её в `bs_main` и генерирует C-`int main(void)`, который сначала выполняет операторы верхнего уровня, затем вызывает `bs_main`.

Пример рекурсии:
```blumscript
func fact(n: int) -> int {
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}
```

## 12. Структуры

```blumscript
struct Point {
    x: int;
    y: int;
}

func main() -> int {
    var p: *Point = cast<*Point>(malloc(sizeof(Point)));
    p->x = 10;
    p->y = 20;
    print("x=", p->x, " y=", p->y);
    free(p);
    return 0;
}
```

- Поля разделяются `;`.
- Доступ по значению: `obj.field`; через указатель: `ptr->field` (или `ptr.field` — компилятор разберётся).
- Структуры можно передавать в функции по значению или по указателю.
- Самореферентные структуры: поле может быть `*Node`.

## 13. Указатели и память

BlumScript даёт C-семантику указателей без скрытых проверок.

### Адрес и разыменование
```blumscript
var n: int = 5;
var p: *int = &n;    // адрес n
*p = 42;             // запись по адресу
print(n);            // 42
```

### malloc / free
```blumscript
var buf: *int = cast<*int>(malloc(sizeof(int) * 16));
buf[0] = 1;
buf[15] = 16;
free(buf);
```

### Массивы и индексация
`a[i]` эквивалентно `*(a + i)` (C-семантика). Границы не проверяются.

### Строки
Строковые литералы имеют тип `string` (`char*`). `len(s)` возвращает длину через `strlen`.

## 14. Встроенные функции и рантайм

Компилятор подставляет реализацию из встроенного рантайма (генерируется в начало `.c`).

| Функция | Сигнатура | Описание |
|---------|-----------|----------|
| `print(...)` | любой набор выражений | Печатает аргументы **без разделителей** и завершает строку `\n` |
| `println(...)` | то же | Синоним `print` |
| `len(s)` | `(string) -> int` | Длина строки (`strlen`) |
| `strlen(s)` | `(string) -> int` | Длина строки |
| `malloc(size)` | `(int) -> *void` | Выделение памяти |
| `free(ptr)` | `(ptr) -> void` | Освобождение памяти |
| `to_int(x)` | `(любое) -> int` | Приведение к `int64_t` |
| `to_float(x)` | `(любое) -> float` | Приведение к `double` |

Печать по типу: `int64_t`, `uint64_t`, `double` (`%g`), `bool`, `char`, `string`, указатель (`%p` или `null`).

Пример:
```blumscript
print("x = ", x, ", y = ", y);   // без пробелов между аргументами
```
Чтобы получить пробелы — добавляйте их в строки: `print("x = ", x, " y = ", y)`.

## 15. Сырые вставки (asm / escape hatch)

Блок `asm { ... }` вставляет своё содержимое **дословно** в сгенерированный C-код. Это позволяет использовать любые C-конструкции, интринсики и (на поддерживаемых платформах) ассемблер.

```blumscript
func main() -> int {
    print("before");
    asm {
        printf("raw C from asm block\n");
    }
    return 0;
}
```

Внутри `asm { }` лексер не разбирает код — блок захватывается целиком с балансировкой скобок.

## 16. Импорты

```blumscript
import "utils.blm";
```

- Директива `import` должна стоять отдельной строкой.
- Путь разрешается относительно текущего файла; расширение `.blm` добавляется автоматически, если не указано.
- Импорты раскрываются рекурсивно; повторные включения одного файла игнорируются (защита от циклов).
- Фактически это текстовая вставка: общие объявления структур/функций становятся доступны.

## 17. Компиляция, диагностика, ограничения

### Генерируемый C
Для `hello.blm` создаётся `hello.c` с:
- встроенным рантаймом (`bs_print_*`);
- `typedef` структур;
- `static` глобальными переменными;
- прототипами и определениями функций;
- `int main(void)` — точка входа.

Показать C: `blumsc build hello.blm --emit-c`.

### Ошибки
Компилятор сообщает об ошибках с указанием токена/сущности:
- неожиданный токен, незакрытая строка/комментарий/`asm`;
- неопределённая переменная/функция;
- несовместимые типы операндов;
- неверное число аргументов;
- неизвестное поле структуры;
- разыменование не-указателя, взятие адреса не-lvalue.

При ошибке `.exe` не создаётся.

### Ограничения текущей версии
- Нет обобщений/шаблонов.
- Нет автоматического управления памятью (только `malloc/free`).
- `let` не проверяет переприсваивание на этапе компиляции (реализуется как обычная переменная).
- Нет строковой конкатенации `+` во время выполнения.
- Нет методов у структур (только свободные функции).
- Нет встроенного `switch` (эмулируется через `if/else if`).
- `asm { }` — это вставка C, а не гарантированный машинный ассемблер (зависит от бэкенда C).
- Массивы в типах поддержаны частично (в объявлениях и `sizeof`); динамические массивы — через указатели + `malloc`.

### Дорожная карта
- Проверка неизменяемости `let`.
- `switch`, `do/while`.
- Методы и `impl`-блоки.
- Настоящий LLVM-бэкенд.
- Автоматический `defer` / RAII.
- Обобщения (generics).

## 18. Полные примеры

### 18.1. Hello + Фибоначчи + циклы

```blumscript
func fib(n: int) -> int {
    var a: int = 0;
    var b: int = 1;
    var i: int = 0;
    while (i < n) {
        let tmp: int = a + b;
        a = b;
        b = tmp;
        i = i + 1;
    }
    return a;
}

func main() -> int {
    print("Hello, BlumScript!");
    print("fib(10) =", fib(10));
    var total: int = 0;
    for (var j: int = 1; j <= 5; j = j + 1) {
        total = total + j;
    }
    print("sum 1..5 =", total);
    if (total == 15) {
        print("math works");
    } else {
        print("math broken");
    }
    return 0;
}
```

Вывод:
```
Hello, BlumScript!
fib(10) =55
sum 1..5 =15
math works
```

### 18.2. Структуры, указатели, malloc, указательная арифметика

```blumscript
struct Point {
    x: int;
    y: int;
}

func dist2(a: *Point, b: *Point) -> int {
    let dx: int = a->x - b->x;
    let dy: int = a->y - b->y;
    return dx * dx + dy * dy;
}

func main() -> int {
    var p: *Point = cast<*Point>(malloc(sizeof(Point)));
    var q: *Point = cast<*Point>(malloc(sizeof(Point)));

    p->x = 1;
    p->y = 2;
    q->x = 4;
    q->y = 6;

    print("p = (", p->x, ",", p->y, ")");
    print("q = (", q->x, ",", q->y, ")");
    print("dist2 =", dist2(p, q));

    var n: int = 5;
    var ptr: *int = &n;
    *ptr = 42;
    print("n after *ptr = 42 ->", n);

    free(p);
    free(q);
    return 0;
}
```

Вывод:
```
p = (1,2)
q = (4,6)
dist2 =25
n after *ptr = 42 ->42
```

## 19. Внутреннее устройство (для разработчиков)

### Лексер
Однопроходный. Поддерживает:
- `//` и `/* */`;
- строки с escape-последовательностями;
- символьные литералы;
- шестнадцатеричные целые (`0x…`);
- захват `asm { … }` с балансировкой вложенных `{}` в отдельный токен `AsmRaw(String)`.

### Парсер
Рекурсивный спуск с явными уровнями приоритета:
```
parse_assignment → parse_or → parse_and → parse_bitor → parse_bitxor
→ parse_bitand → parse_equality → parse_relational → parse_shift
→ parse_additive → parse_multiplicative → parse_unary → parse_postfix → parse_primary
```
Типы разбираются функцией `parse_type`: префиксные `*`, базовое имя, суффикс `[N]`.

### Кодогенератор
- Проход 1: собирает структуры и сигнатуры функций.
- Проход 2: собирает глобальные переменные и выводит их типы.
- Генерация: структуры → глобалы → прототипы → функции → `main`.
- Выражения возвращают пару `(C-код, тип)`; для операторов выполняется проверка типов и выбор результирующего типа.
- Встроенные функции (`print`, `malloc`, `len`, `free`, `to_int`, `to_float`, `strlen`) разворачиваются в вызовы рантайма/C.

### Драйвер
- `expand_imports` — рекурсивное включение;
- `find_vcvars` — `BLUM_VCVARS` → `vswhere` → стандартные пути;
- `compile_c` — `cmd /C call vcvars64.bat && cl …` (Windows) или `gcc/clang` (иначе);
- `run_exe` — запуск собранного файла с пробросом кода возврата.

## 20. Лицензия и статус

BlumScript 0.2.0 — рабочий прототип компилятора: покрывает типизированные функции, структуры, указатели, ручную память, циклы, условия, выражения, импорты и вставки C. Используется как полноценный нативный компилятор для Windows (MSVC) и кросс-платформенно (gcc/clang).

Для сборки компилятора и примеров достаточно Rust + C-компилятора; внешних зависимостей у компилятора нет.
