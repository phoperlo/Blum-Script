# BlumScript — полная документация

**Версия:** 1.0.0
**Компилятор:** `blumsc` (Rust)
**Бэкенд:** прямой кодоген x86-64 → собственный PE32+ writer (без C, без ассемблера, без LLVM)

---

## 1. Что такое BlumScript

BlumScript — универсальный компилируемый язык, спроектированный с двумя целями одновременно:

1. **Низкий порог входа.** Все ключевые слова — обычные английские слова (`let`, `var`, `func`, `if`, `else`, `while`, `for`, `return`, `struct`, `import`, `and`, `or`, `not`, `sizeof`, `cast`). Синтаксис читается как псевдокод.
2. **Максимальные возможности.** Язык даёт прямой доступ к памяти: указатели, `malloc`/`free`, арифметика указателей, `&`/`*`, `->`, `sizeof`, приведение типов `cast<T>(...)`, сырые вставки машинного кода через `asm { ... }`.

Один и тот же язык позволяет писать:
- высокоуровневые приложения (функции, структуры, циклы, строки);
- низкоуровневый код (ручное управление памятью, указательная арифметика, работа с сырой памятью).

**Модель исполнения.** Компилятор сам порождает машинные инструкции x86-64 и сам собирает из них исполняемый файл `PE32+` (`.exe`) — включая заголовки, секции, таблицу импорта и рантайм. Ни C-файла, ни внешнего ассемблера, ни линковщика, ни LLVM-IR в цепочке нет. Никакой VM и интерпретации в рантайме: полученный `.exe` — обычная нативная программа под Windows x64 с соглашением вызова Microsoft x64.

## 2. Архитектура компилятора

```
исходник .blm
   │
   ├─ imports::expand_imports   — рекурсивное раскрытие import "..."
   ├─ lexer::lex                — токенизация
   ├─ parser::parse_program     — рекурсивный спуск → AST
   ├─ native::compile           — проверка типов + кодоген x86-64
   │     ├─ runtime::emit       — рантайм-рутины (print, strlen, malloc/free)
   │     │                        тоже машинным кодом, тем же эмиттером
   │     └─ x64::Asm            — байтовый эмиттер инструкций, метки, фиксапы
   └─ pe::link / pe::write_exe  — PE32+ заголовки, секции, импорт-таблица → .exe
```

Модули (`src/`):

| Файл | Назначение |
|------|------------|
| `lexer.rs`   | Токены, литералы, комментарии, `asm { … }` как сырой блок |
| `ast.rs`     | Определения AST (выражения, операторы, объявления) |
| `parser.rs`  | Рекурсивный спуск, приоритеты операторов, разбор типов |
| `types.rs`   | Система типов |
| `x64.rs`     | Кодировщик x86-64: REX/ModRM/SIB, mov/lea/арифметика/imul/idiv/setcc/jcc/call, метки и фиксапы (`Local`, `Iat`, `Rdata`, `Data`) |
| `native.rs`  | Семантика + генерация кода: раскладка структур, локалы от `RBP`, выражения → `RAX`, вызовы по Windows x64 ABI, `print` по статическим типам |
| `runtime.rs` | Рантайм на машинном коде: `bs_write`, `bs_print_int/uint/hex/str`, `bs_strlen`, `bs_malloc`, `bs_free` |
| `abi.rs`     | Смещения в `.data`, индексы IAT, список импортов `kernel32.dll` |
| `pe.rs`      | PE32+ writer: секции `.text/.rdata/.data/.idata`, ILT/IAT, резолвинг фиксапов, запись файла |
| `imports.rs` | Раскрытие `import` и запуск собранного `.exe` |
| `main.rs`    | CLI `blumsc` |

Семантический анализ выполняется в `native` (вывод типов, проверка областей видимости, полей структур, сигнатур функций, типов операндов). При ошибке компиляция останавливается до записи `.exe`.

**Точка входа.** Компилятор генерирует собственную entry-точку: она получает `STDOUT_HANDLE`, выполняет инициализацию глобалов и операторы верхнего уровня, вызывает пользовательский `main` и завершает процесс через `ExitProcess(return value)`.

## 4. Быстрый старт

Создайте `hello.blm`:

```blumscript
func main() -> int {
    print("Hello, BlumScript!");
    return 0;
}
```

Сборка и запуск:

```powershell
blumsc run hello.blm
```

Вывод:

```
built: hello.exe
Hello, BlumScript!
```

Или отдельно:

```powershell
blumsc build hello.blm -o hello.exe
.\hello.exe
```

## 5. CLI

```
blumsc build <file.blm> [-o output.exe] [--emit-bytes]
blumsc run   <file.blm> [--emit-bytes]
blumsc check <file.blm>
blumsc tokens <file.blm>
blumsc ast    <file.blm>
blumsc hex    <file.blm>
```

| Команда | Действие |
|---------|----------|
| `build` | Скомпилировать в `.exe`. `-o` задаёт имя. `--emit-bytes` печатает сгенерированный машинный код hex-дампом. |
| `run`   | Собрать и сразу запустить. Код возврата программы пробрасывается. |
| `check` | Только лексика + парсинг + семантика/кодоген. Ничего не пишет на диск. |
| `tokens`| Дамп токенов. |
| `ast`   | Дамп AST в отладочном виде. |
| `hex`   | Синоним `build --emit-bytes`. |
| `-h`, `--help` | Справка. |
| `-V`, `--version` | Версия. |

## 6. Лексика

### Комментарии
```blumscript
// однострочный
/* многострочный
   комментарий */
```

### Литералы

| Вид | Пример |
|-----|--------|
| Целое | `42`, `0`, `1000000`, `0xFF`, `0x1F` |
| Дробное | `3.14`, `0.5`, `2.0` |
| Строка | `"hello"`, `"line\nbreak"`, `"\t"`, `"\"quoted\""` |
| Символ | `'a'`, `'\n'`, `'\\'` |
| Логические | `true`, `false` |
| Нулевой указатель | `null` |

Экранирование строк: `\n`, `\t`, `\r`, `\0`, `\\`, `\"`.

### Идентификаторы
Начинаются с латинской буквы или `_`, далее буквы, цифры, `_`. Регистрозависимы.

### Ключевые слова
`let`, `var`, `func`, `if`, `else`, `while`, `for`, `return`, `break`, `continue`, `true`, `false`, `null`, `struct`, `import`, `asm`, `sizeof`, `cast`, `and`, `or`, `not`.

### Операторы
`+  -  *  /  %` — арифметика
`<  >  <=  >=  ==  !=` — сравнения/равенство
`and  or  not`, `&&  ||  !` — логика
`&  |  ^  ~  <<  >>` — битовые
`=` — присваивание
`&` — адрес, `*` — разыменование (унарные)
`.` и `->` — доступ к полю структуры
`[]` — индексация
`()` — вызов/группировка

## 7. Типы

### Примитивы

| BlumScript | Размер | Описание |
|------------|--------|----------|
| `bool`   | 1 байт  | логический (`true` / `false`) |
| `char`   | 1 байт  | символ (ASCII) |
| `byte`   | 1 байт  | беззнаковый байт |
| `int`    | 8 байт  | знаковое 64-бит |
| `uint`   | 8 байт  | беззнаковое 64-бит |
| `float`  | 8 байт  | IEEE-754 double, кодоген на SSE2 (`movsd`, `addsd`, `ucomisd`, …) |
| `string` | 8 байт  | указатель на строку (NUL-terminated) |
| `void`   | —       | отсутствие значения |

`int` — 64-битный регистр целиком; в машинном коде это `RAX`, `RCX`, `RDX`, … и адресация `[base + disp32]`.

### Производные типы

```blumscript
*int          // указатель на int
**int         // указатель на указатель
*Point        // указатель на структуру Point
int[16]       // массив из 16 int (в типах)
```

### Приведение типов

```blumscript
cast<*int>(malloc(sizeof(int)))   // void* → *int
cast<string>(ptr)                 // любой указатель → string
cast<int>(byteValue)              // расширение до 64 бит
```

Приведение в нативном бэкенде не меняет биты: значение уже лежит в `RAX` как 64-битное, тип меняется только в семантике (важно для печати и арифметики указателей).

### Размер типа

```blumscript
sizeof(int)     // 8
sizeof(Point)   // размер структуры
```

## 8. Переменные и области видимости

```blumscript
let x: int = 10;       // let — «неизменяемая» по замыслу (в C статически не проверяется на переприсваивание)
var y: int = 20;       // var — изменяемая
let z = 5;             // тип выводится из инициализатора
```

- `var` может объявляться без инициализатора — тогда память обнуляется (для агрегатов целиком).
- Явная аннотация типа пишется через `:`.
- Если тип указан явно, значение приводится к нему на уровне семантики.
- Область видимости — блок `{ }`. Вложенные блоки могут перекрывать имена.
- **Глобальные переменные:** объявления `let`/`var` верхнего уровня размещаются в секции `.data` PE-образа и инициализируются в entry-точке до вызова `main`. Они видны из всех функций.
- Присваивание возможно как простой переменной, так и lvalue: полю структуры (`p.x = …`, `p->x = …`), элементу массива (`a[i] = …`), разыменованному указателю (`*p = …`).

## 9. Выражения

### Арифметика и сравнения
```blumscript
let a: int = 10 + 3 * 2;      // 16
let b: float = 3.5 / 2.0;
let c: bool = a >= 15 and a != 7;
let d: int = a % 5;
```

### Логика
`and` / `&&`, `or` / `||`, `not` / `!` — с коротким замыканием (C-семантика).

### Вещественные числа

`float` — это `double` (8 байт, IEEE-754). Кодоген использует SSE2, значение
живёт в `XMM0`, поэтому арифметика и сравнения не пересекаются с целочисленным
`RAX`.

```blumscript
let a: float = 3.5;
let b: float = a / 2.0;      // 1.75
let c: bool = a > 3.0;       // true
let d: int = to_int(b);      // 1
let e: float = cast<float>(7);
```

- Операторы: `+ - * /`, унарный `-`, сравнения `== != < > <= >=`. `%`, `&`, `|`, `^`, `<<`, `>>` для `float` — ошибка компиляции.
- Смешанная арифметика (`x + 1`) разрешена: целое приводится к `double` автоматически; результат — `float`.
- Неявные преобразования работают в объявлении, присваивании, аргументах и `return`: `var i: int = 5.5;` даёт `5`, `var f: float = 5;` даёт `5.0`.
- Условия `if`/`while`/`for` и `!` трактуют `0.0` и `-0.0` как ложь, `NaN` — как истину (C-семантика).
- Передача в функции: первые четыре `float`-аргумента — `XMM0..XMM3`, остальные — через стек; `int`-аргументы нумеруются отдельно в `RCX/RDX/R8/R9`.
- Печать (`print`) выводит 6 знаков после точки, отдельно обрабатывает `nan`, `inf`, `-inf`.
- Литералы хранятся в `.rdata` с выравниванием 8 и дедуплицируются по битам.

### Битовые операции
```blumscript
let mask: int = 1 << 4;       // 16
let inv: int = ~mask;
let x: int = 0xF0 | 0x0F;
```

### Приоритет операторов (от низкого к высокому)

1. `=` (присваивание, правоассоциативное)
2. `or`, `||`
3. `and`, `&&`
4. `|`
5. `^`
6. `&`
7. `==`, `!=`
8. `<`, `>`, `<=`, `>=`
9. `<<`, `>>`
10. `+`, `-`
11. `*`, `/`, `%`
12. унарные `-`, `not`, `~`, `*`, `&`
13. постфиксные: вызов, `[]`, `.`, `->`

### Указательная арифметика
```blumscript
var arr: *int = cast<*int>(malloc(sizeof(int) * 10));
arr[0] = 1;          // индекс
*(arr + 1) = 2;      // арифметика указателей + разыменование
```

### Доступ к полям
```blumscript
p.x        // структура по значению
p->x       // структура через указатель
```
Компилятор сам выбирает `.` или `->` в зависимости от типа базы, но синтаксис тоже учитывается.

## 10. Управляющие конструкции

### if / else
```blumscript
if (x > 0) {
    print("positive");
} else if (x < 0) {
    print("negative");
} else {
    print("zero");
}
```
`else if` поддерживается напрямую (как цепочка условий).

### while
```blumscript
var i: int = 0;
while (i < 10) {
    i = i + 1;
}
```

### for
Трёхчастный, как в C:
```blumscript
for (var i: int = 0; i < 10; i = i + 1) {
    print(i);
}
```
Допустимы `let`/`var` в инициализации, присваивание или выражение — в обновлении.

### break / continue
```blumscript
for (var i: int = 0; i < 100; i = i + 1) {
    if (i == 5) { break; }
    if (i % 2 == 0) { continue; }
    print(i);
}
```

### return
```blumscript
return 0;
return x + 1;
```

### Блок
```blumscript
{
    let tmp: int = 42;
}
```

## 11. Функции

```blumscript
func add(a: int, b: int) -> int {
    return a + b;
}

func greet(name: string) {
    print("Hello, ", name);
}
```

Правила:
- Параметры типизированы: `имя: тип`.
- Возвращаемый тип указывается через `-> тип`. Если отсутствует — `void`.
- Вызов: `add(3, 4)`, `greet("world")`.
- Значения передаются в регистрах `RCX, RDX, R8, R9`, остальные — через стек; на стеке резервируется shadow space 32 байта, стек выравнивается на 16 (соглашение Microsoft x64).
- Поддерживается рекурсия.
- Тип возврата компилятор не приводит автоматически: `return` оставляет в `RAX` то, что там оказалось. Приводите явно (`cast<int>(…)`), если нужно иное представление.
- Функции не могут принимать и возвращать структуры по значению — передавайте `*Struct`. Это ограничение 1.0.0, а не языка.
- Точка входа: `func main() -> int`. Компилятор генерирует PE-entry, который инициализирует глобалы, выполняет операторы верхнего уровня, вызывает `main` и делает `ExitProcess(результат)`.

Пример рекурсии:
```blumscript
func fact(n: int) -> int {
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}
```

## 12. Структуры

```blumscript
struct Point {
    x: int;
    y: int;
}

func main() -> int {
    var p: *Point = cast<*Point>(malloc(sizeof(Point)));
    p->x = 10;
    p->y = 20;
    print("x=", p->x, " y=", p->y);
    free(p);
    return 0;
}
```

- Поля разделяются `;`.
- Доступ по значению: `obj.field`; через указатель: `ptr->field` (или `ptr.field` — компилятор разберётся).
- Раскладка: поля выравниваются по своему размеру, размер структуры округляется вверх до 8 байт. `sizeof(Point)` для двух `int` даёт 16.
- Локальная структура объявляется без инициализатора (`var p: Point;`) — память под неё обнуляется; для `*Point` — `malloc`.
- Передача структуры в функцию — только по указателю `*Struct`.
- Самореферентные структуры: поле может быть `*Node`.

## 13. Указатели и память

BlumScript даёт C-семантику указателей без скрытых проверок.

### Адрес и разыменование
```blumscript
var n: int = 5;
var p: *int = &n;    // адрес n
*p = 42;             // запись по адресу
print(n);            // 42
```

### malloc / free
```blumscript
var buf: *int = cast<*int>(malloc(sizeof(int) * 16));
buf[0] = 1;
buf[15] = 16;
free(buf);
```

### Массивы и индексация
`a[i]` эквивалентно `*(a + i)` (C-семантика). Границы не проверяются.

### Строки
Строковые литералы имеют тип `string` и размещаются в секции `.rdata` готового `.exe`. `len(s)` возвращает длину (свой `bs_strlen` на машинном коде).

## 14. Встроенные функции и рантайм

Рантайм написан машинным кодом тем же эмиттером (`src/runtime.rs`) и линкуется в `.text` каждой программы. Внешние зависимости — только `kernel32.dll`: `GetStdHandle`, `WriteFile`, `ReadFile`, `ExitProcess`, `GetProcessHeap`, `HeapAlloc`, `HeapFree`, `CreateFileA`, `CloseHandle`, `GetFileSizeEx`.

| Функция | Сигнатура | Описание |
|---------|-----------|----------|
| `print(...)` | любой набор выражений | Печатает аргументы **без разделителей** и завершает строку `\n` |
| `println(...)` | то же | Синоним `print` |
| `len(s)` | `(string) -> int` | Длина строки |
| `strlen(s)` | `(string) -> int` | Длина строки |
| `malloc(size)` | `(int) -> *void` | `HeapAlloc(GetProcessHeap(), 0, size)` |
| `free(ptr)` | `(ptr) -> void` | `HeapFree(GetProcessHeap(), 0, ptr)` — безопасен для `null` |
| `to_int(x)` | `(любое) -> int` | Для `float` — `cvttsd2si` (усечение к нулю, как в C); для остальных значение уже 64-битное |
| `to_float(x)` | `(любое) -> float` | Для целого — `cvtsi2sd`; для `float` — без изменений |
| `read_str()` | `() -> string` | Читает строку с консоли (до `\n`), возвращает свежую копию в heap |
| `read_int()` | `() -> int` | Читает строку и разбирает знак и цифры; `0`, если цифр нет |
| `read_char()` | `() -> char` | Читает строку, возвращает первый символ |
| `open(path, mode)` | `(string, int) -> *void` | `CreateFileA`: `0` — чтение, `1` — запись (создать/усечь), `2` — чтение+запись (открыть/создать) |
| `read(h, buf, len)` | `(*void, *byte, int) -> int` | `ReadFile`, возвращает число прочитанных байт |
| `write(h, buf, len)` | `(*void, *byte, int) -> int` | `WriteFile`, возвращает число записанных байт |
| `file_size(h)` | `(*void) -> int` | `GetFileSizeEx` |
| `close(h)` | `(*void) -> void` | `CloseHandle` |

### Ввод с консоли и файлы

```blumscript
func main() -> int {
    print("name:");
    var name: string = read_str();

    print("age:");
    var age: int = read_int();
    print(name, " is ", age);

    var h: *void = open("notes.txt", 1);
    write(h, "hello file\n", 11);
    close(h);

    var r: *void = open("notes.txt", 0);
    print("size = ", file_size(r));
    var buf: *byte = cast<*byte>(malloc(64));
    var n: int = read(r, buf, 63);
    buf[n] = 0;
    close(r);
    print(cast<string>(buf));
    free(buf);
    return 0;
}
```

`read_str` не разделяет общий буфер между вызовами: каждая строка — отдельный `HeapAlloc`, освобождать через `free`. `read`/`write` работают с любыми буферами (`*byte`, `malloc`, адрес массива через `cast<*byte>(&a[0])`).

Печать выбирается по **статическому типу** аргумента на этапе компиляции, никакого varargs нет:

| Тип | Что делает кодоген |
|-----|--------------------|
| `int` | `bs_print_int` — десятичное, со знаком |
| `uint`, `byte` | `bs_print_uint` — десятичное, без знака |
| `char` | один байт в буфер `.data` + `WriteFile` |
| `bool` | `true` / `false` |
| `string` | `bs_print_str` (для `null` печатает `null`) |
| указатель, структура, массив | `bs_print_hex` — вида `0x1a2b3c` |

Вся запись идёт через `WriteFile` с кэшированным `STDOUT_HANDLE`, поэтому вывод корректно перенаправляется в файл/пайп.

Пример:
```blumscript
print("x = ", x, ", y = ", y);   // без пробелов между аргументами
```
Чтобы получить пробелы — добавляйте их в строки: `print("x = ", x, " y = ", y)`.

## 15. Сырые вставки (asm / escape hatch)

Блок `asm { ... }` — это escape hatch в машинный код. Внутри блока ожидаются **hex-байты**; они копируются в `.text` дословно, в позицию текущей инструкции. Никакого ассемблера и парсинга: что написали — то и исполнится.

```blumscript
func main() -> int {
    print("before");
    asm {
        // mov rax, 42
        48 c7 c0 2a 00 00 00
        // nop nop
        90 90
    }
    print("after");
    return 0;
}
```

Принимаются формы `48 c7 c0 2a 00 00 00`, `48,c7,c0,2a`, `0x48 0xC7` — разделители: пробел, запятая, `;`. Не-hex токен — ошибка компиляции: `asm: 'xyz' is not a hex byte`.

Через `asm` можно писать что угодно: менять регистры, вызывать WinAPI напрямую (адреса импортов при этом придётся резолвить вручную), вставлять `int3`, `ud2`, `cpuid`, `rdtsc` и т.п. Блок не влияет на кадр стека — за сохранность `RBP/RSP/RAX` отвечает автор блока.

## 16. Импорты

```blumscript
import "utils.blm";
```

- Директива `import` должна стоять отдельной строкой.
- Путь разрешается относительно текущего файла; расширение `.blm` добавляется автоматически, если не указано.
- Импорты раскрываются рекурсивно; повторные включения одного файла игнорируются (защита от циклов).
- Фактически это текстовая вставка: общие объявления структур/функций становятся доступны.

## 17. Компиляция, диагностика, ограничения

### Что генерируется
Для `hello.blm` создаётся `hello.exe` — законченный `PE32+` образ:
- `.text` — машинный код всех функций, entry-точки и рантайма;
- `.rdata` — строковые литералы;
- `.data` — кэш `STDOUT_HANDLE`, буфер `char` и глобальные переменные;
- `.idata` — таблица импорта `kernel32.dll` (ILT, IAT, hint/name, имя DLL).

Размер типичного hello-бинарника — около 3.5 КБ. Показать кодоген: `blumsc build hello.blm --emit-bytes` (hex-дамп `.text`).

### Ошибки
Компилятор сообщает об ошибках с указанием сущности:
- неожиданный токен, незакрытая строка/комментарий/`asm`;
- неопределённая переменная/функция;
- несовместимые типы операндов;
- неверное число аргументов;
- неизвестное поле структуры;
- разыменование не-указателя;
- `asm`-токен, который не является hex-байтом;
- агрегат (структура/массив) в позиции, где нужен скаляр ≤ 8 байт.

При ошибке `.exe` не создаётся.

### Ограничения текущей версии
- Нет обобщений/шаблонов.
- Нет автоматического управления памятью (только `malloc/free`).
- `let` не проверяет переприсваивание на этапе компиляции (реализуется как обычная переменная).
- Нет строковой конкатенации `+` во время выполнения.
- Нет методов у структур (только свободные функции).
- Нет встроенного `switch` (эмулируется через `if/else if`).
- Структуры нельзя передавать и возвращать по значению — только через указатель.
- Агрегаты нельзя инициализировать значением: `var a: int[5];` создаётся и обнуляется, заполнение — поэлементное.
- `asm { }` — это raw-байты, а не текст ассемблера: мнемоники вида `mov rax, 42` не разбираются, нужны байты.
- Строки, прочитанные `read_str()`, не освобождаются автоматически — вызывайте `free()`.

### Дорожная карта
- Проверка неизменяемости `let`.
- `switch`, `do/while`.
- Методы и `impl`-блоки.
- Структуры по значению в аргументах и возврате (ABI-классификатор).
- Автоматический `defer` / RAII.
- Обобщения (generics).

## 18. Полные примеры

### 18.1. Hello + Фибоначчи + циклы

```blumscript
func fib(n: int) -> int {
    var a: int = 0;
    var b: int = 1;
    var i: int = 0;
    while (i < n) {
        let tmp: int = a + b;
        a = b;
        b = tmp;
        i = i + 1;
    }
    return a;
}

func main() -> int {
    print("Hello, BlumScript!");
    print("fib(10) =", fib(10));
    var total: int = 0;
    for (var j: int = 1; j <= 5; j = j + 1) {
        total = total + j;
    }
    print("sum 1..5 =", total);
    if (total == 15) {
        print("math works");
    } else {
        print("math broken");
    }
    return 0;
}
```

Вывод:
```
Hello, BlumScript!
fib(10) =55
sum 1..5 =15
math works
```

### 18.2. Структуры, указатели, malloc, указательная арифметика

```blumscript
struct Point {
    x: int;
    y: int;
}

func dist2(a: *Point, b: *Point) -> int {
    let dx: int = a->x - b->x;
    let dy: int = a->y - b->y;
    return dx * dx + dy * dy;
}

func main() -> int {
    var p: *Point = cast<*Point>(malloc(sizeof(Point)));
    var q: *Point = cast<*Point>(malloc(sizeof(Point)));

    p->x = 1;
    p->y = 2;
    q->x = 4;
    q->y = 6;

    print("p = (", p->x, ",", p->y, ")");
    print("q = (", q->x, ",", q->y, ")");
    print("dist2 =", dist2(p, q));

    var n: int = 5;
    var ptr: *int = &n;
    *ptr = 42;
    print("n after *ptr = 42 ->", n);

    free(p);
    free(q);
    return 0;
}
```

Вывод:
```
p = (1,2)
q = (4,6)
dist2 =25
n after *ptr = 42 ->42
```

## 19. Внутреннее устройство (для разработчиков)

### Лексер
Однопроходный. Поддерживает:
- `//` и `/* */`;
- строки с escape-последовательностями;
- символьные литералы;
- шестнадцатеричные целые (`0x…`);
- захват `asm { … }` с балансировкой вложенных `{}` в отдельный токен `AsmRaw(String)`;
- BOM в начале файла игнорируется.

### Парсер
Рекурсивный спуск с явными уровнями приоритета:
```
parse_assignment → parse_or → parse_and → parse_bitor → parse_bitxor
→ parse_bitand → parse_equality → parse_relational → parse_shift
→ parse_additive → parse_multiplicative → parse_unary → parse_postfix → parse_primary
```
Типы разбираются функцией `parse_type`: префиксные `*`, базовое имя, суффикс `[N]`.

### Кодогенератор (`native.rs`)
- Проход 1: раскладка структур (поля, выравнивание, размер), сигнатуры функций, глобалы в `.data`.
- Проход 2: функции и entry-точка. Тело функции пишется в общий буфер, пролог с финальным размером кадра патчится после (`sub rsp, imm32` с плейсхолдером).
- Инвариант: любое выражение оставляет результат в `RAX`. Бинарные операции — `push`/`pop` через стек, локалы — `[RBP - off]`, `disp32` везде.
- Адресация lvalue: `addr(expr)` → адрес в `RAX` (`lea [rbp-off]`, `lea [rip+imm]`, разыменование, `+field offset`, `+index * sizeof`), затем load/store нужной ширины.
- Индексация масштабируется умножением на `sizeof` элемента (без SIB-индексов — `imul rcx`).
- Циклы: `break`/`continue` — стеки меток; `continue` в `for` идёт на метку апдейта.
- `print` разрешается по статическому типу каждого аргумента, поэтому varargs не нужен.
- `asm { }` — hex-байты копируются в `.text` дословно.

### Ассемблер (`x64.rs`)
Тонкая обёртка над байтами: REX/ModRM/SIB, `mov/lea/movzx`, `add/sub/imul/idiv/div/neg/not`, `and/or/xor/test/cmp`, сдвиги через `CL`, `setcc`, `push/pop`, `jmp/jcc/call`, rip-relative load/store. Все ветвления и обращения к данным — через фиксапы (`Local`, `Iat`, `Rdata`, `Data`), которые резолвит линкер.

### PE-линкер (`pe.rs`)
- Секции `.text`, `.rdata`, `.data`, `.idata`; выравнивание 0x1000 / 0x200, база `0x140000000`.
- Таблица импорта: descriptor, ILT, IAT, hint/name, имя DLL; каталог импорта в optional header.
- После раскладки RVAs все фиксапы превращаются в `rel32` (защита от переполнения диапазона — ошибка линковки).
- Optional header: `PE32+`, subsystem `CONSOLE`, NX compatible, large address aware.

### Драйвер (`imports.rs`, `main.rs`)
- `expand_imports` — рекурсивное включение с защитой от циклов;
- `run_exe` — запуск собранного файла с пробросом кода возврата.

## 20. Лицензия и статус

BlumScript 1.0.0 — компилятор с собственным нативным бэкендом: AST превращается в машинные инструкции x86-64, из которых тут же собирается `PE32+` под Windows. Покрыты типизированные функции, структуры, указатели, ручная память, массивы, циклы, условия, выражения, импорты и raw-вставки машинного кода.

Для сборки компилятора достаточно Rust. Ни C-компилятора, ни ассемблера, ни линковщика, ни LLVM не требуется, внешних зависимостей у компилятора нет.
